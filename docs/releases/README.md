# LDForge project release notes

This is the project-wide release history. Each Markdown file records package
version transitions, functionality and upgrade guidance for one release batch.
The demo's [Release notes page](https://ldforge.nl/releases.html) renders the same
files, and new GitHub releases use the committed Markdown as their description.
Package-specific changelogs remain available in each package.

Normal release notes are generated by `npm run release:prepare` from the exact
release record in `.releases/`. Add curated project highlights and migration
examples to `editorial.json` before preparing, keyed by a unique changeset ID.
Include GitHub issue references such as `#11` where verified. Without editorial
content, changeset summaries become the project-wide change list. The generator
includes all packages participating in the batch, including rebuilt bundles.

Review generated notes before `release:push`. API and user-visible behavior
changes need explicit upgrade guidance; do not infer compatibility from a version
number alone. The website reads committed Markdown at build time and needs no
GitHub API, credentials or runtime network request.

Historical `v*` entries were reconstructed from successfully published GitHub
releases, their tagged package manifests and intervening commit subjects. They
are labelled as reconstructed rather than complete migration documentation.
`v0.1.10` is intentionally absent: its tag was not a published release. Existing
batch releases use their exact records, rather than inferred versions.

To regenerate notes for an existing batch after editing editorial content:

```sh
node scripts/project-release-notes.mjs .releases/<release-tag>.json
```

Never modify an existing release's package versions or tags when correcting prose.
