01 / INTEGRATE

Choose how to load LDForge

Use CDN imports for a single static HTML page, or npm with a bundler for an existing application. Both approaches use the same editor and plugin APIs.

CDN: start with a single HTML file

Try the live Wikidata cat grid, then download its HTML or copy the source into your own static site. No npm, framework, API key or Node server is required. Serve the file over HTTP(S).

Three version-pinned esm.sh imports provide the HTTP executor, editor and cards renderer. Load the editor stylesheet separately: 

import { createHttpExecutor } from 'https://esm.sh/@ldforge/core@0.1.2?standalone';
import { createEditor } from 'https://esm.sh/@ldforge/editor@0.1.2?standalone';
import { createCardsRenderer } from 'https://esm.sh/@ldforge/renderers@0.1.2?standalone';
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@ldforge/editor@0.1.2/dist/styles.css" />

Use ?standalone to bundle the editor’s dependencies into one module: no import map is needed. Keep all LDForge URLs on the same version. CSS is loaded separately from jsDelivr. The example connects to https://query.wikidata.org/sparql using GET and calls editor.run() once on load. Remove that call to wait for a click on Run query. Internet access is required.

The query selects twelve domestic cats with images. Its # view=cards header selects the card grid; card_title, card_text, card_image, card_button and card_button_url map the result columns to each card. Links to Wikidata let visitors find the original images and licenses. The public endpoint may be busy; Run query retries the request.

npm: install in your application

LDForge packages provide ESM JavaScript and TypeScript declarations. Install them in your own application: 

npm install @ldforge/core @ldforge/editor @ldforge/renderers @ldforge/prefixes

Use a browser bundler with CSS imports, such as Vite. No framework is required. The editor depends on core and the prefix catalog; the renderer package supplies independent result views. See the configuration reference for every option and default.

02 / EMBED

Mount a working editor

Add a container to your page or host component:

<div id="query-editor"></div>

Then mount the editor from your TypeScript entry point. Replace the example URL with your own SPARQL endpoint: 

import { createHttpExecutor } from '@ldforge/core';
import { createEditor } from '@ldforge/editor';
import {
  createTableRenderer,
  createBooleanRenderer,
  createJsonRenderer,
} from '@ldforge/renderers';
import '@ldforge/editor/styles.css';

const container = document.querySelector<HTMLElement>('#query-editor');
if (!container) throw new Error('Missing editor container');

const editor = createEditor(container, {
  query: 'SELECT * WHERE { ?s ?p ?o } LIMIT 10',
  executor: createHttpExecutor({
    endpoint: 'https://your-endpoint.example/sparql',
  }),
  renderers: [
    createTableRenderer(),
    createBooleanRenderer(),
    createJsonRenderer(),
  ],
});

The default toolbar includes Run query and Cancel. Run with the button or Ctrl/Cmd+Enter. SELECT produces bindings; ASK produces a boolean. CONSTRUCT, DESCRIBE and SPARQL Update are not supported by this initial HTTP adapter.

Connecting from a browser

Your endpoint must support the chosen method: direct POST with application/sparql-query, or GET with a query parameter. It must return SPARQL Results JSON and allow your application's origin and extra headers through CORS. If it cannot, route requests through your own backend. Private server credentials belong on that backend.

Configure requests inside the IDE

Open the gear button in the demo's toolbar for endpoint settings. Choose a saved endpoint, select GET or POST, and add header name/value pairs such as Authorization with a Bearer token. Select Apply endpoint to activate your changes. Endpoint URLs and methods are remembered; header values stay in memory for this page only and are kept separate per endpoint.

For your own integration, configure the executor directly:

const executor = createHttpExecutor({
  endpoint: 'https://your-endpoint.example/sparql',
  method: 'GET', // Defaults to 'POST'.
  headers: { 'X-Project': 'catalogue' },
});

Use the editor's settings option to register host-owned settings panels. A settings plugin has an id, a label, and a render(container, context) function. Return cleanup when needed. An optional updateLocale(container, context) updates labels without replacing inputs. The demo's src/endpoint-settings.ts is a complete example. The library manages Accept and Content-Type; authentication policy stays with the host.

The status below the query reports completion, for example 3 results in 124 ms. Durations scale to seconds, minutes or hours. This measures execution and result parsing, before rendering.

Configure the IDE and control individual tabs

The right-side icon group contains Prefixes, Format query and Settings. Hide individual built-in controls through the controls object. Project buttons appear in a separate group; hiding a tool does not disable its API. 

// In createEditor options:
// controls: { prefixes: true, format: true, settings: true, closeTab: false }

const tabs = editor.getTabs();
const first = tabs[0];
first?.addPrefix('sdo', 'https://schema.org/');
first?.addPrefix('dct');
const other = tabs.addTab({
  name: 'People', query: 'select * where {?s ?p ?o}',
  prefixes: ['sdo', 'dct'], activate: false,
});
await other.formatQuery();
tabs.getByName('People')?.activate();

Queries are formatted locally, with the formatter loaded on first use. Invalid text stays intact. Inactive tabs can be edited without opening another editor. Read the Editor, TabCollection and QueryTabHandle references for return values, callbacks and error behavior.

The demo restores your last applied endpoint and method on refresh. It does not automatically execute a query or store authentication header values.

SPARQL-aware editing and prefixes

Press Ctrl+Space for suggestions. The editor uses a Lezer syntax tree to recognize SERVICE, FILTER and triple positions. Predicates are suggested only in predicate positions, including property paths and semicolon shorthand. Variable suggestions use previous syntactic names in the visible query scope. Comments, strings and IRI contents are excluded.

Selecting a predicate such as rdfs:label inserts its missing PREFIX automatically in the same undoable edit. Use the Prefixes button in the toolbar to search common namespaces by prefix or namespace URI and add them directly. Existing aliases are reused; conflicting names get a free suffix. 

import { prefixes, prefixEntries, searchPrefixes } from '@ldforge/prefixes';

searchPrefixes('prov');
// In createEditor options:
// sparql: {
//   prefixes: { ...prefixes, ex: 'https://example.org/' },
//   autoPrefixes: false, // Optional: disable automatic declarations while typing.
//   predicates: [
//     { iri: 'https://example.org/name', description: 'Resource name' },
//   ],
// }

The standalone prefix package offers a compact catalog of 32 mappings and an extended catalog of 3,623 mappings, without labels. Neither variant has dependencies or network calls. Import from @ldforge/prefixes/compact or @ldforge/prefixes/extended and pass its prefixes map to the editor. Compact does not load extended data. Omit predicates for the small built-in RDF vocabulary, or provide your own. Syntax errors are marked at parser recovery ranges; known undeclared prefixes offer a quick fix. This checks local syntax and prefix declarations, not whether an endpoint supports or can successfully execute a query.

Group related toolbar plugins with a group identifier, such as group: 'examples'. The IDE combines these into compact button groups. Tab actions appear on hover or keyboard focus; double-clicking a tab name still starts renaming.

03 / ADD ACTIONS

Bring your own buttons

A button plugin receives a typed editor context. Supplying buttons replaces the toolbar, so include the built-in factories to keep Run and Cancel. Add this to your editor options: 

import { createRunButton, createCancelButton } from '@ldforge/editor';
import type { ButtonPlugin } from '@ldforge/core';

const loadExample: ButtonPlugin = {
  id: 'my-project.load-example',
  label: 'Load example',
  isDisabled: (context) => context.getState().status === 'running',
  execute(context) {
    context.setQuery('ASK { ?subject ?predicate ?object }');
  },
};

// In createEditor(container, { ... }):
// buttons: [createRunButton(), createCancelButton(), loadExample]

Use getQuery(), setQuery(), getState(), run() and cancel() in your action. Actions may return promises; rejected actions are shown in the status message. Give each button a unique, non-empty identifier.

04 / RENDER RESULTS

Choose how results are presented

Renderers are separate from the editor. Each plugin declares which results it supports. Register your own view alongside the built-in views: 

import type { ResultRendererPlugin } from '@ldforge/core';

const countRenderer: ResultRendererPlugin = {
  id: 'my-project.count',
  label: 'Row count',
  supports: (result) => result.kind === 'bindings',
  render(container, result) {
    if (result.kind !== 'bindings') return;
    const paragraph = container.ownerDocument.createElement('p');
    paragraph.textContent = `${result.bindings.length} rows`;
    container.replaceChildren(paragraph);
    return () => paragraph.remove();
  },
};

// In createEditor(container, { ... }):
// renderers: [countRenderer, createTableRenderer(), createJsonRenderer()]

Bindings contain ordered variable names and rows of RDF terms; unbound variables are absent from a row. Boolean results contain a value. Use textContent for RDF values. Return a cleanup function when allocating listeners, charts or framework components; it runs before the next render and on destruction.

The result tabs only offer supported views. Renderers can supply an optional icon factory; CSV download exports the full result independently of the selected tab. Registration order determines the initial view. JSON view displays LDForge's normalized result model. For large results, limit your query or supply a paginated or virtualized renderer.

05 / CONNECT YOUR HOST

Own the transport and lifecycle

For a custom backend, implement QueryExecutor and pass it as executor. This example assumes your backend accepts JSON and responds with SPARQL Results JSON: 

import { parseSparqlResults } from '@ldforge/core';
import type { QueryExecutor } from '@ldforge/core';

const executor: QueryExecutor = {
  async execute({ query, signal }) {
    const response = await fetch('/api/sparql', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ query }),
      signal,
    });
    if (!response.ok) throw new Error(`Query failed: ${response.status}`);
    return parseSparqlResults(await response.json());
  },
};

Forward the abort signal. LDForge cancels superseded queries and ignores stale replies. The host manages authentication and endpoint policy. 

// Synchronize edits with your host through a createEditor option:
// onQueryChange: (query) => { /* update your host state */ }

editor.getQuery();
editor.setQuery('ASK { ?s ?p ?o }');
await editor.run();
editor.cancel();

// On component unmount, before removing the container:
editor.destroy();

In React, Vue or another framework, mount the editor after the container exists and call destroy() in the component's cleanup hook. Each mount is independent. Plugin registration is static per mount; recreate the editor when changing the plugin set.

Customize the appearance with scoped CSS variables:

.ldforge {
  --ldforge-accent: #075e55;
  --ldforge-border: #d6dedd;
}

06 / TABS AND LANGUAGE

Several queries, one editor

Use + to add a query tab. Double-click its name or use the pencil button to rename it. Enter or leaving the field saves the name; Escape cancels. The demo saves query text, titles and the active tab to localStorage while editing and switching tabs.

LDForge keeps one CodeMirror view and one active editor state. Inactive tabs contain plain text only. Switching cancels pending execution, clears the previous result and resets undo history, so undo cannot cross query boundaries. Your host owns persistence through these options: 

import { parseQueryWorkspace } from '@ldforge/editor';
import type { QueryWorkspace } from '@ldforge/editor';

function restoreWorkspace(): QueryWorkspace | undefined {
  try {
    return parseQueryWorkspace(JSON.parse(
      localStorage.getItem('my-project.queries') ?? 'null',
    ));
  } catch {
    return undefined;
  }
}

function saveWorkspace(workspace: QueryWorkspace) {
  try {
    localStorage.setItem('my-project.queries', JSON.stringify(workspace));
  } catch {
    // Editing can continue when storage is unavailable.
  }
}

// Pass the restored value as workspace when present, and use:
// onWorkspaceChange: saveWorkspace
// Read the current snapshot with editor.getWorkspace().

English and Dutch, chosen by your users

The IDE follows the browser's first supported language and falls back to English. A project setting overrides browser detection, and a user choice under the gear button overrides the project. Choosing the default restores the project/browser preference. The demo remembers the user's choice. This integration guide and the demo's surrounding introduction remain in English. 

// In createEditor(container, { ... }):
// locale: 'auto',       // Or 'en' / 'nl' as the project default.
// userLocale: 'nl',     // Optional restored user override.
// onLocaleChange: (preference) => { /* persist in your host */ }

editor.setLocale('nl');
editor.setLocale('auto'); // Restore the project/browser default.

Plugin labels accept a string or an object such as { en: 'My action', nl: 'Mijn actie' }. Renderer plugins receive the active locale as their optional third argument. Language changes preserve query text and settings drafts. RDF values and SPARQL code are not translated.
